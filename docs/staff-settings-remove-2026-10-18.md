# Administrator Settings entry removal — 18 October 2026

Scope: Settings only. Dashboard customisation was cancelled and its unpublished draft removed. Existing add/edit controls remain in their sections; the new Remove Settings entries section lists cakes, sizes, flavours, delivery areas, closed days, occasions and occasion dates. Staff access and access-level removal remain in Team and access.

Removal requires an administrator, a selected entry and confirmation naming it. The server compares the expected entry name/date/size against the current row, uses a fixed table allowlist, and rejects non-admin requests. Used cakes and catalogue entries, used sizes/flavours, used delivery areas and used occasions are protected. The UI explains how to take these off sale or archive instead. System/merged occasions, custom-cake entry and the last active size are protected. Removing an unused occasion also removes its dates; unused cake removal includes its option rows. Orders, payments and customer records are not removed by this API.

Backend migration: admin_settings_entry_removal. Public SECURITY INVOKER wrapper calls the administrator-checked implementation in non-exposed staff_config_api with an empty search_path. Execute is denied to PUBLIC/anon. Removal snapshots and actor/time are retained in a private RLS-enabled, no-client-grant removal_log; deny-all/no-policy advisor notice on this private audit table is intentional. Existing unrelated project advisor warnings were not changed.
